# Build Note — SudSwitch Prototype

---

## 1. What Was Built

A static single-page application (HTML/CSS/JS) deployable to GitHub Pages. The tool takes five user inputs via a form, fetches live EU new vehicle registration data from the Eurostat API at form submission, then renders a savings comparison card with a monthly cost delta, a charging readiness indicator, and a context strip that displays the Italy/Spain BEV share figures pulled directly from the API response — not hardcoded. No server, no backend, no build step.

---

## 2. The Live Data Query Used

**Endpoint:** `https://ec.europa.eu/eurostat/api/dissemination/statistics/1.0/data/road_eqr_carpda`

**Parameters (constructed at runtime from user input):**
- `format=JSON`
- `geo=IT` or `geo=ES` — set dynamically from the country selector
- `geo=EU27_2020` — fetched in the same call to produce the EU average comparator
- `vehicle=ELC` — filters to battery electric vehicles only
- `unit=PC` — percentage share of new registrations
- `time=2021&time=2022&time=2023` — three years pulled to show the flat/declining trend Marlowe identified

The fetch fires on form submission (the "Calculate" button press), not on page load. The raw JSON is parsed in the browser; the Italy 4.2% and EU 14.5% figures displayed in the context strip come directly from the parsed response object, keyed to `2023` and the relevant `geo` dimension. If the API returns an error or times out, the context strip displays a fallback message: "Live EU data temporarily unavailable — figures shown are from the most recent cached Eurostat release" with the static values substituted. This is the only place a fallback value appears, and it is labeled as such.

## 3. What's on Screen and How It Updates

**On page load:**
The intake form renders immediately from static HTML. No API call is made. The page is functional without a network request at this stage.

**Screen 1 — Intake Form:**
Five inputs rendered sequentially:
1. Country toggle (Italy / Spain) — sets subsidy path and API geo parameter
2. City dropdown (Milan, Rome, Madrid, Barcelona) — maps to a hardcoded charging density category (dense / moderate / sparse); this lookup is a static JS object, not an API call, because no suitable public endpoint exists for city-level charging point density at the granularity needed
3. Monthly fuel spend slider (€50–€300)
4. Parking situation radio group (private garage / workplace available / street only)
5. Daily km range radio group (under 30 / 30–60 / 60–100 / over 100)

"Calculate" button is disabled until all five fields have a value.

**On "Calculate" press:**
1. `fetch()` fires to the Eurostat endpoint with the constructed parameter string
2. A loading state replaces the button label ("Fetching EU data…")
3. On successful response: the savings card (Screen 2) replaces Screen 1 in the DOM via a CSS class toggle; no page navigation, no reload
4. On fetch failure: the savings card still renders using the labeled static fallback for the context strip; the rest of the card uses only the locally-computed subsidy/cost figures, which are unaffected by the API

**Screen 2 — Savings Card:**
- Two-column cost comparison: "Your current car (est.)" vs "CityVolt (est.)" with explicit line items — fuel/electricity, maintenance delta (fixed estimate: –€35/month, described in UI as a rough average), subsidy amortised over 48 months
- Single headline delta in large type (e.g., "–€87/month")
- Charging readiness badge: green / amber / red, derived from the parking input, with a one-line explanation
- Context strip: "X% of new cars sold in [country] in 2023 were electric — vs Y% EU average. This figure is live from Eurostat." X and Y are the parsed API values
- CTA button: label and destination URL vary based on delta sign and charging badge color (positive delta + green/amber → test drive lead form; negative delta or red → waitlist form)

The "Edit inputs" link at the bottom of Screen 2 restores Screen 1 with values preserved. Pressing "Calculate" again fires a fresh fetch.

## 4. What Was Cut and Why

**Cut: The shareable result card.**

Iris flagged this as "optional, low-build-cost" but generating a genuine shareable image card (Open Graph image with dynamic text, or even a canvas-rendered PNG) is not achievable in a static site without either a serverless function for image generation or a third-party service dependency. A plain text share via the Web Share API (`navigator.share()`) is technically possible but would share a URL with no pre-rendered preview, which defeats the peer-loop mechanic Iris described. The mechanic only works if the shared link renders a card with the user's specific number on social platforms — that requires dynamic Open Graph meta tags at serve time, which GitHub Pages cannot produce per-request. Including a broken or degraded version of this feature would undermine trust in the savings figures elsewhere on the page. It is cut entirely from this prototype; it is a viable feature addition if the project moves to a server-rendered deployment.
